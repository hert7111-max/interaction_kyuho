# CRT Arcade

입체적인 3D 방 안에서 CRT를 바라보는 1인칭 카메라 게임입니다. 책상, 창문과 저녁 도시, 두꺼운 모니터, 스피커, 머그컵, 유선 컨트롤러와 양손을 실제 3D 지오메트리로 구성했습니다. 화면에는 안내문 대신 카메라·초기화·전체 화면 아이콘과 예제 메뉴를 표시합니다.

카메라 아이콘으로 시작한 뒤 엄지를 세우고 검지를 뻗고 나머지 손가락을 접으면 손가락 총이 됩니다. 총구 방향으로 초당 12발씩 발사하며 실제 탄환이 위로 비행하는 전투기와 충돌합니다. 양손 동시 사격, 작은 조준 보조, 폭발·연기·중력 낙하와 점수를 지원합니다. 실제 눈 윤곽에는 사격 중 흰 빛과 청록색 광원이 번쩍입니다. 손의 관절 굽힘, 엄지 이동과 움직임 크기는 컨트롤러의 손가락·엄지·스틱·버튼·트리거 모션으로 이어집니다.

전투기는 8가지 실루엣과 색상의 사전 렌더링 픽셀 스프라이트입니다. 카메라와 게임은 640×480 캔버스에 함께 그리며, 볼록한 4:3 유리 표면의 셰이더가 스캔라인·색 번짐·미세한 가로 흔들림·롤링 밴드·노이즈·비네트를 적용합니다. 웹페이지의 방 전체가 아닌 모니터 안에 VHS 효과를 둡니다.

정적인 방 지오메트리는 재질별로 합쳐 호출 수를 줄이고, 전투기·탄환·효과는 상한과 객체 풀을 사용합니다. 모니터 캔버스는 30Hz, 3D/물리는 최대 60Hz, DPR은 1.35로 제한합니다. MediaPipe는 한 번에 한 프레임을 처리하고 처리 시간에 따라 추론 빈도를 조절합니다. 기존 GPU→CPU, Worker→DOM, ImageBitmap→ImageData 대체 경로를 공유합니다. 숨김 상태에서는 렌더링·추론·카메라를 일시 정지합니다.

```sh
npm test
npm run build
```

기존 게임 검사는 계속 통과합니다. 신규 검사는 총 자세와 열린 손 구분, 8종 기체·상승, 연사 속도·중단, 탄환 충돌·점수·폭발·연기·중력 낙하, 양손 독립 사격, 조준 반대편 오격추 방지, 장시간 객체 수 제한과 초기화를 확인합니다. 로컬에서 서버 없이 자체 완결 HTML로 구동한 3D 장면과 CRT 셰이더, 샘플 이미지·제어 입력을 시각 확인했습니다. 실제 카메라 손/눈 추적과 모바일 기기 검증은 아직 완료하지 못했습니다.

`scripts/arcade-browser-qa.ts`는 공식 Google 샘플 사진과 합성 손 입력·눈 윤곽으로 장면을 확인하는 개발용 파일입니다. 배포에는 포함하지 않습니다. 카메라 영상은 기기 내에서 처리하며 HTTPS와 카메라 권한이 필요합니다. 3D에는 WebGL2가 필요합니다.

## 손·컨트롤러와 방 개선

회색 컨트롤러의 둥근 하우징과 그립, D패드·스틱·심벌 버튼을 새로 모델링했습니다. 손은 손목·손바닥·엄지 밑살·다섯 손가락을 하나로 융합한 닫힌 피부 메쉬로 만들었습니다. 별도 부품을 겹치던 엄지 뿌리와 손목 경계가 없으며, 피부 결·얕은 마디 주름·손톱 높이를 사진의 자세에 맞춰 보정했습니다. 엄지 패드가 실제 버튼 높이에 닿고 나머지 손가락은 그립 뒤쪽으로 말립니다. 기존 MediaPipe 기반 버튼·트리거·손가락 모션을 유지합니다.

카메라에 붙은 컨트롤러 단자와 모니터 왼쪽 단자를 매 프레임 월드 좌표로 구해 하나의 연속된 케이블을 갱신합니다. 시점·화면 비율과 반동이 달라져도 양 끝이 단자에 고정됩니다. 케이블의 위치·법선 버퍼는 재사용합니다.

방은 목재 책상과 금속 다리, 카펫, 실제 창문 개구부와 건물, 커튼, 책꽂이·광학 디스크 콘솔·CD 케이스·과자·캔·머그·램프를 입체 지오메트리로 구성했습니다. 재질의 거칠기·반사, 둥근 모서리, 따뜻한 램프와 차가운 창문 조명, 캐시한 1024px 그림자로 깊이를 표현합니다. 정적인 지오메트리는 재질별로 병합하고 손 형태는 `npm run build:arcade-hand`로 오프라인에서 미리 계산합니다. 실행 중에는 양손 각각 하나의 GPU 스킨 메쉬와 본 변형만 사용하며, 복잡한 표면을 매 프레임 재생성하지 않습니다.

자동 검사 58개를 통과했습니다. 추가 검사는 케이블 양 끝의 일치, 시점/세로 화면 변경 시 연결 유지, 버퍼 재사용, 피부 메쉬의 단일 연결 성분과 열린 경계 없음, 양손의 정상 방향, 엄지 변형 중 손목 고정과 스킨 가중치를 확인합니다. 이전 손 버전의 Chrome 샘플 입력 100프레임에서 장면과 그립·케이블 연결을 시각 검증했고, 렌더 호출 120회·약 11만 삼각형, CPU 업데이트+렌더 제출 p95 3.9ms를 관측했습니다. 이 수치는 해당 Mac 한 대의 이전 버전 합성 입력 검증이며 이번 변경의 성능 측정치나 추론 시간·실제 카메라 추적·모든 기기의 성능을 뜻하지 않습니다.

## HP·적 탄환·콤보

MediaPipe의 기존 얼굴 모델에서 36점 얼굴 윤곽을 함께 받아, 카메라와 같은 cover·미러 좌표로 변환합니다. 전투기는 현재 얼굴 중심을 향해 적색 탄환을 쏩니다. 탄환 이동 선분과 얼굴 다각형의 교차를 검사해 빠른 탄환도 놓치지 않으며, 얼굴을 감싼 사각형의 빈 모서리는 맞지 않습니다. Easy 설정으로 한 번 맞으면 5 HP의 피해를 초당 8 HP 속도로 나누어 적용하며, 0.9초 중복 피격 보호를 둡니다. 적 발사 간격은 2.8~4.4초, 탄속은 105~133px/s로 완화했습니다.

HP 0에서는 사격이 멈추고 현재 얼굴 영상이 작은 블록으로 폭발합니다. 원래 얼굴의 어긋난 파편, 그을음과 균열이 남고 9개 불꽃·13개 연기 스프라이트·18개 불씨가 계속 움직입니다. 얼굴이 화면 밖에 0.25초 이상 머무르면 초당 60 HP를 충전하므로, 완전 소진에서도 약 1.92초면 회복합니다. 완전히 충전하면 재등장할 수 있습니다. 카메라 꺼짐, 추론 중단, 탭 숨김은 충전으로 취급하지 않습니다. 화면 위쪽에는 점수·콤보, 얼굴 위에는 HP를 5×7 비트맵 글씨와 분절 막대로 표시합니다. 웹폰트를 다운로드하지 않습니다. 격추마다 콤보 +1, 중복 격추는 제외하고, 기체가 위로 탈출하거나 HP가 소진되면 콤보를 초기화합니다.

검지는 양손 모두 컨트롤러의 어깨 버튼 위로 감아 보이도록 동일한 연결 피부 메쉬 안에서 재제작했습니다. 사격 시 12Hz 검지·엄지 누름, 트리거·버튼·스틱과 본체 반동을 확대했습니다. 여전히 손당 GPU 스킨 메쉬 한 개, 적 탄환 최대 64개, 기존 객체 풀과 30Hz 모니터 갱신을 사용합니다.

추가 자동 검사는 실제 윤곽 충돌·빗나감, 적 탄환 발사·상한, 시간 분할 피해, 일회성 폭발·사격 중단, 화면 밖 충전·부활, 인식 중단 시 충전 차단, 콤보·초기화, 공유 모델의 얼굴 윤곽 출력과 양손 검지의 가시 범위·누름 변형을 확인합니다. Chrome의 합성 입력으로 HP 감소·격추 콤보·얼굴 파편과 재충전 표시를 확인했습니다. 실제 카메라 입력 및 모바일 실기 검증은 별도로 필요합니다.

## 손등·Easy·참고 사진 구도 보정

검지 길이를 줄여 어깨 버튼에 감기는 곡선을 만들고 검지 중수골과 손등을 넓게 연결했습니다. 모든 손가락을 곡선으로 샘플링한 뒤 피부 표면을 오프라인으로 굽습니다. 메쉬는 여전히 단일 연결·닫힌 표면이고, 검지 뿌리에서 손등으로 가는 폭이 좁은 막대처럼 되지 않는지 검사합니다. 엄지와 본체의 기존 사격 모션은 유지합니다.

시점은 중앙에서 0.1만 벗어난 앉은 위치와 43도 화각으로 조정했습니다. 모니터를 더 뒤에서 바라보고 컨트롤러는 아래쪽의 작은 전경으로 배치해 게임 화면을 덜 가립니다. 검정·녹색 CRT 케이스, 수평에 가까운 책상 원근, 왼쪽 창의 푸른 빛, 오른쪽 주황색 스탠드와 코르크 메모 보드·사진·CD·선인장을 구성했습니다. 정적인 방은 계속 재질별 병합과 캐시한 그림자를 사용합니다.

최종 자동 검사 58개와 TypeScript 검사를 통과했습니다. 추가로 10초 동안 매 프레임 적탄을 맞아도 살아남는지, HP 0에서 2초 이내 충전되는지, 4가지 화면 비율에서 CRT가 잘리지 않고 책상 양쪽의 높이가 수평으로 보이는지 검사합니다. 이번 변경의 브라우저 미리보기는 브라우저 연결이 중단되어 시각 검증을 완료하지 못했습니다.
